# TWIN VECTOR

二層の搬送路を守る、1980年代初期風の固定画面シューティング。
別層で進めた弾をシールドと本体の間へ送り込み、敵を撃破する。
9セクターの編隊戦、6系統の通常敵、3機の大型敵、一周後のネームエントリーと
トップ5を収録。一周は強いbotで約5分。残機3から始まり、15,000点と以後20,000点ごとに1機増える。

## 起動・操作

`index.html` をブラウザで開く。ビルド、外部素材、CDN、ネット接続は不要。
HTTPならリポジトリルートから：

```sh
python3 -m http.server 5173 --directory docs/twin-vector
```

`http://localhost:5173` にアクセス。

| 操作 | キー |
|---|---|
| 開始・射撃・決定 | Space / Enter / Z / X（押しっぱなしで連射） |
| 左右のレーン移動 | ← → / A D |
| 上の層へ（自機と未転送弾を移す） | ↑ / W |
| 下の層へ（自機と未転送弾を移す） | ↓ / S |
| 一時停止・復帰 | P |
| 消音 | M |
| ネーム入力の文字変更 | ↑ ↓ / W S |
| ネーム入力の位置変更 | ← → / A D |
| 文字決定／ENDで保存 | Space / Enter / Z / X |

短押しを保持し、切替には12フレーム、射撃には8フレームの受付猶予がある。フォーカスを失う・別のタブへ移るとゲーム中は停止し、Space/Enter/Z/X/P・タップで復帰（復帰のキーでは撃たない）。
ネーム入力は20秒で自動確定、ランキングは8秒後にデモへ戻る。
ゲーム中の簡易ポインター操作は左右端で移動＋射撃、中央の上半分／下半分で上／下の層へ移動＋射撃。
ネーム入力を含む正式な対象はキーボード。タッチ実機は未検証。

## タグ・表現

最初の `node tools/pick-tags.mjs` の結果を再抽選せず使用。

- `pseudo-3D`：奥へ狭まる5レーン、座標投影、スプライトの縮尺。
- `two layers`：A/Bの二層と、飛行中の弾の経路選択。大型敵も二層の部位が連動する。

256×288、8色、整数ラスタの線と独自ビットマップ文字・スプライト。
グラデーション、ブルーム、半透明効果、ポストエフェクト、カメラズームなし。
READYやクリアは盤面の隙間に等倍文字のみを出す。背景パネル・囲み枠なし。
タイトルではゲームと同じエンジンへ操作を送る無音デモを流す。

32段4bitウェーブテーブル3声＋LFSRノイズ1声のモノラル、残響なし。特定基板の厳密なエミュレーションではなく
**era-inspired**。15の効果音・ジングル・開始曲と、接近ビート・ネーム入力曲の2つの常時音。[AUDIO.md](AUDIO.md)
絵・文字・音は本作のコードで生成し、外部素材なし。コードはリポジトリと同じISC。

## 主な判断

水色の弾は切替時に反対層へ移り、金色になる。一発の転送は一度だけ。
金色になった弾は以後その層に残る。

- 通常敵：通常弾100点、転送弾300点。
- 装甲敵：本体より奥行き0.30だけ手前に、独立したシールドを持つ。
  正面からは転送弾でも遮られる。別層で盾を越えた弾を隙間へ送る。
- 装甲敵の進軍は通常より20%遅い。弾速0.020/tickで、隙間の通過は約0.25秒。
- 桃色の敵：矢印の予告後、一度隣のレーンへ移る。
- 白いシフター：進行方向と移動先の枠を約1秒予告し、反対層へ一度移る。
  早く撃破するか、移動に合わせて飛行中の弾も転送する。
- 金色のガード：左右を含む3レーンを一枚の盾で守る。ガードを先に落とすか、
  隣の敵の背後へ弾を送るかを選ぶ。盾の幅と当たり判定は対応している。
- 赤いガンナー：一度停止し、砲口の予告後に0.4秒間隔で三連射して進軍を再開する。
- 接触弾・敵侵入で1機失う。敵はミスで消えず、得点も入らない。
- 盾が自機を通り過ぎれば、本体は正面からも撃てる。

射撃した層と命中させる層を分けて考える。敵弾回避の切替で未転送弾も動くため、
安全な退避先と弾の送り先が一致するとは限らない。
金色の認識に頼らず、盾・本体・弾の位置関係で成功を読めることを重視する。

## セクターと大型敵

速度だけを増やさず、編隊の関係と休止で各面を分ける。配置は左右／層の位相を
シードで変え、無関係な乱数位置へは置かない。

| 面 | 編隊・目的 | 機数 | 大型敵 |
|---|---|---:|---|
| 1 PAIRED PATROL | 同じレーンへ上下の敵が時間差で来る | 12 | — |
| 2 PINCER | 装甲敵と反対層の敵による挟撃 | 16 | — |
| 3 CROSS TRAFFIC | 装甲と横移動敵、時間差の追撃 | 20 | DREADNOUGHT |
| 4 LAYER HOP | シフターを単独に近い配置で紹介 | 12 | — |
| 5 SHIELD CONVOY | ガードと隣レーンの被護衛機 | 16 | — |
| 6 SIEGE LINE | ガンナー、シフター、装甲の組み合わせ | 12 | BULWARK |
| 7 SHIFT PURSUIT | 両層のシフターと横移動敵 | 15 | — |
| 8 CROSS GUARD | 広い盾の下の砲撃と別層からの接近 | 16 | — |
| 9 LAST VECTOR | 全要素を使った時間差編隊 | 20 | PHASE CARRIER |

新敵は4〜6面で紹介し、7〜9面で混成する。4面は3面ボス後の休息も兼ねる。
基礎進軍速度は3面の値で上限となり、後半を速度だけで難しくしない。
各編隊の間隔・機種・レーン関係は `rounds.js` のデータに記録。

- 3面：左右移動する盾付き砲台と、両層にまたがるコア。砲台1基でB層の盾が周期開口、2基で開口延長。
- 6面：盾付き砲台をA/Bに分割。壊した砲台の反対層が開き、両方破壊でA/B交互に長く開口。本体3,000点。
- 9面：6面の盾構造に、予告付きで層移動する単一の弱点コアを追加。開口層とコア所在層が一致したときに命中。本体5,000点。

全ボスの砲台は隙間への転送で破壊する。本体は開口から撃破できる。3面の本体は2,000点。
ボス撃破で残機は回復しない。9面の最後はALL CLEARからネーム入力へ進む。10面はない。

各面の500点ボーナスを100点ずつ加算する。通常機139、砲台6、本体3の最大計148機（3面では残存砲台を省略可能）。
理論最高点は **58,000点**（139×300＋6×300＋2,000＋3,000＋5,000＋9×500）。
強いbotの実測は57,600〜57,800点。ミスによる敵の復帰で得点を再獲得することはない。

ゲームオーバー／ALL CLEAR → 入賞なら3文字入力 → トップ5 → 無音デモ。
入賞しない場合は入力を省略。デフォルト順位は12,000/8,000/4,000/2,000/500点。
同点は新しい記録を優先し、保存するのは実際のプレイ記録だけ。
保存不能なブラウザでもゲームを継続する。残機の追加は得点によるエクステンドのみ（下記）。

## 同じ認知制約botでの比較・調整

[HUMAN_MODEL.md](HUMAN_MODEL.md) の最短操作0.2秒、反対側の確認約1.2秒ごと、
切替後の再認識0.4秒、見落とし・記憶失効を固定。
新しく観察できる広い盾の被覆とガンナーの停止だけを読み取りに追加した。
未観察の層、移動先の未来状態、出現キューを直接参照することはない。

3面ボス改修前の記録：同じ60シード（201–260）で旧3面版と9面版を比較：

| 指標 | 旧3面版 | 9面版 |
|---|---:|---:|
| 平均得点 | 9,460 | 15,068 |
| 点数範囲 | 3,400–12,300 | 3,400–37,200 |
| 平均プレイ時間 | 93秒 | 161秒 |
| 最終面到達 | 53/60（3面） | 7/60（9面） |
| 一周クリア | 30/60 | 2/60 |

9面版の各面到達数：60 / 60 / 53 / 30 / 30 / 29 / 14 / 11 / 7。
強いbotは元の12シードすべて完走。固定往復botと放置・定位置射撃は完走なし。
認知制約botで各面を**個別に残機3から**開始した場合、12シード中のクリア数は
12 / 10 / 8 / 12 / 12 / 10 / 11 / 11 / 12。この個別試験は通し完走の証拠ではない。

調整点：シフターが層移動前に倒され続けたため、予告開始を進軍深度0.32から0.12へ早めた。
予告時間は60tickを維持。新敵の役割を残し、後半の累積消耗に対しては3面ごとの補給を採用（後に得点エクステンドへ置換）。
1機だけ回復した試行では60回中完走0、3機への補給後は2回。後半の難易度はまだ高い。

データ：`evidence/nine-stage-balance.json`、比較用旧版：`evidence/three-stage/`。
人間による9面版の難易度・手応えは未確認であり、次のプレイ報告を優先する。

## ゲームフィール

短押し入力、1ピクセルの射撃反動、切替点滅、射撃・横移動の予告を維持。
通常撃破・盾への反射・転送撃破をドットと音で分ける。盾は本体爆発後に落下。
大型敵では共通の船体、砲台、閉鎖シャッター、砲台と連動する表示を描き分け、
本体の爆発を大きくした。得点加算は短い電子音で刻む。
ネーム入力も同じ文字・パレット・音を使い、Webフォームは設けない。

### レーン投影の修正

横方向の縮尺と縦方向の奥行きを共通化し、端の敵も直線グリッドのレーン中央を通るよう修正。
敵の浮き高さも縮小した。両レイヤー・全5レーン・5深度で中央との誤差は浮動小数点の丸め範囲。

### 3面ボス改修：移動する二層盾

左右の砲台は通常の隙間転送で破壊できる盾を持つ。ボスは4秒周期で
左右へ1レーンずつ移動し、移動前には方向を予告する。中央コアは両層に
またがる1体で、初期状態では両層とも盾の裏への転送を含め完全防御。
砲台を1基破壊するとB層の中央盾が周期的に開く。予告0.5秒、開口1.2秒。
2基破壊すると開口が2秒に延びる。予告と開口中は位置を固定する。
残存砲台を残してコアを倒してもクリアするが、その砲台の撃破点は得られない。
6・9面は下記「ボスの段階構成」で追加改修済み。

認知制約の各定数は維持し、両層に見えるコアと各層の盾状態だけを遅延観測に追加。
3面開始・残機3・seed 1〜12の比較では、強いbotが12/12、認知制約botが6/12、
押しっぱなし・連打botは0/12突破。`evidence/dreadnought-balance.json` に記録。
以前の9面通しの結果はこの改修前の記録であり、現在の通し難易度を示さない。
人間による改修ボスの評価は未実施。

追加検証：`node docs/twin-vector/tests/dreadnought.cjs`。
完全防御、砲台への隙間転送、片側開口、開口延長、停止・移動・pause、
残存砲台を残したクリアを検証。同じ検証をブラウザでも実行する。

3面ボスの追加18項目はNodeとChromiumの両方で成功。最終ブラウザ検証52項目、実行時エラー0。

### ボスの段階構成（現行）

3面は固定のB開口を学ぶ。6面は砲台の破壊順で攻撃する層を選ぶ。
9面は同じ盾構造に移動する弱点を重ね、開口と到着を合わせて先行射撃できる。
全ボスは閉鎖中だけ横移動し、開口中は照準を固定できる。
6・9面ではA砲台を壊すとB、B砲台を壊すとAが開く。両方破壊すると
4秒周期ごとにA/B交互に開き、開口が1.2秒から2秒に延長する。
9面のコア移動は約1秒予告する。閉鎖側、または弱点がまだ不在の層への
命中では倒せない。片砲台だけを壊した場合でも、以降の完全な各周期には
必ず弱点と開口の一致時間がある。コア先行撃破でもクリアできる。

検証コマンド：

```sh
node docs/twin-vector/tests/boss-progression.cjs
node docs/twin-vector/tests/boss-balance.cjs
```

ボス進行60項目（逆側の防御、先行射撃、両破壊の交互開口、停止・再開・
リスタートを含む）に成功。ブラウザ操作・音声等の50チェックも成功。
認知制約は従来のままで、実際に見える弱点所在層を遅延観測へ追加。
残機3でボスだけを開始したseed 201〜260の結果は3面58/60、6面51/60、
9面51/60突破。平均所要14/16/18秒。6面と9面の成功率に差はなく、
9面が人間に確実に難しいとまでは判断していない。
強いbotは各12/12突破、6面5秒・9面9秒。連打巡回も各12/12突破するが
6・9面は29秒。押しっぱなしは0/12。ボス自体に乱数はなく、これらの
非確率的ポリシーの12回は同じ動作の再現であり独立した戦術例ではない。
巡回連打でも攻略できる余地は残るが、強いbotの方が早く攻略する。
9面通しは強いbot12/12完走、認知制約bot2/60完走・平均14,635点、タイムアウト0。
結果は `evidence/boss-progression-balance.json`。人間による手応えの評価は未実施。

### 移動先表示と迎撃ボーナス

フィールドのA/B文字と、敵の移動方向を示す > < V ^ は削除。
横移動・層移動とも移動先の点滅する四隅だけで予告する。
実際の横レーン移動・層移動から30フレーム未満（0.5秒）で倒すと+200点。
通常100、転送300、移動直後300、移動直後かつ転送500点。
通常の前進、出現、予告だけでは対象にならない。ボスの横移動・コアの層移動も
対象で、コアは従来の撃破点に+200点。盾への命中だけでは加点しない。
対象時間中は敵の両脇の小さな金色の点、撃破時は合計得点で示す。
移動先を読んだ迎撃を報いるための追加で、0.5秒の手応えは人間には未評価。

`node docs/twin-vector/tests/intercept.cjs` は11項目を検証。
30フレーム境界、転送との重複、二重撃破防止、盾ブロック、前進の除外を含む。
既存の得点記録と理論最高点はこのボーナス導入前の値。

### ゲームフィール改修（2026-09-29）

`maximizing-game-feel` に沿って、隙間への転送を最も強い反応にそろえた。ルール・当たり判定・得点は不変。
旧エンジンと同じ入力列を40シード与え、fx以外の状態とイベントが全ティック一致することを確認した。

- 不具合修正：層切替音の優先度を95から65へ下げた。切替直後の転送撃破・盾反射の音が
  切替音に押しのけられて消えていた（隙間の奥で当たる短い転送ほど無音だった）。
  6・9面ボス本体の撃破が通常撃破と同じ大きさで描かれていた問題を修正。
  シャッター開閉が撃破の爆発で描かれていたのを、バーが左右へ滑る表現に変更。
- 射撃の短押しを8フレーム保持する。切替の12フレーム保持と同じ扱い。

### 1980年代アーケード風の見た目と音（2026-09-29）

**ビジュアル**
- 敵は2コマアニメの3色スプライト（本体・目・アクセント）。移動・層移動・砲撃の予告中は
  コマ送りが約3倍速になり、予告の手がかりを増やす。自機は噴射口が明滅する。

### ボスのコア：開いた層は「通り道」（2026-09-29）

旧仕様ではシャッターが開いた層でコアを正面から撃てたため、最後の撃破だけ中心の技能を使わなかった。
現在はコアが**片方の層にだけ存在し、通常の盾付きの敵と同じく常に前に盾を持つ**。
反対の層のシャッターが開いたときだけ、開いた層で撃って盾の位置を越え、コアの層の隙間へ転送すると倒せる。
早すぎる転送はコアの盾に当たり、遅すぎる転送は本体の脇を抜ける。

- 3面：コアはA層に固定。砲台を1基壊すとB層が周期的に開く（72tick、2基で120tick）。
- 6面：A砲台を壊すとB、B砲台を壊すとAが開く。コアは閉鎖中（30tick）に予告つきで開く層の反対側へ移り、
  開口時（90tick）には到着済み。両方壊すと開く層が周期ごとに交互になり、コアも毎周期移る。
- 9面：コアは開口より遅れて120tickに到着し、210tickに予告つきで去る。開いた直後はまだ開いた層に
  コアの盾があり、到着を待ってから撃つ必要がある。片方の砲台だけでも各周期に必ず窓がある。
- コアに届くのは転送した弾だけ。層を移ってきたコアの隙間に普通の弾が居合わせても弾かれる
  （押しっぱなしbotがコアの到着に合わせて倒せてしまう抜け道が見つかったため）。
- 表示：コアの層には金の盾、反対の層は閉じたシャッター（3本線）か開いた通り道（左右の支柱）。
  コアのいない層の本体は暗い殻として描く。遅すぎた転送の表示もコアに出る。

認知制約botの観測：コアの層を見ているときは反対層のシャッターの開閉も読める（船体が両層にまたがる
一つの絵のため）。開いた層を見ているときはコアが反対の層にいると読める。未来の周期は読まない。

ボス単体（残機3から、seed 201〜260、`tests/boss-balance.cjs`）：

| | 3面 | 6面 | 9面 |
|---|---:|---:|---:|
| 強いbot | 12/12・5秒 | 12/12・9秒 | 12/12・5秒 |
| 認知制約bot | 59/60・18秒 | 59/60・17秒 | 59/60・19秒 |
| 連打巡回 | 12/12・15秒 | 12/12・14秒 | 12/12・14秒 |
| 押しっぱなし | 0/12 | 0/12 | 0/12 |

旧仕様では認知制約botが58/51/51、連打巡回が6・9面で29秒。コアが通常の盾付きの敵と同じ攻略になったため、
認知制約botは安定して倒せるようになった。一方で**連打巡回（常時射撃・3回/秒の切替・左右往復）が
認知制約botより速く倒す**。ランダムな転送でも隙間に入るためで、未解決の弱点として残す。
通し（認知制約bot・射撃先行入力あり、seed 201〜260）は完走2/60・9面到達5/60（変更前4/60・9/60）。
強いbotは12/12完走。人間による評価は未実施。

検査：`tests/dreadnought.cjs`（19項目）、`tests/boss-progression.cjs`（82項目：正面射撃は盾、
開いた層に本体なし、実際の射撃→転送での撃破、交互開口、9面の到着前後、到着したコアが普通の弾を弾く、
予告、停止・死亡・再開）。ブラウザ53項目、フィール15項目も成功。

### 毎回変わる展開と、広い盾の敵の配置（2026-09-29）

以前はページを開いた直後の1回目が常にシード1983で、乱数の消費も操作に左右されないため毎回同じ展開だった。
現在は開始のたびに時刻からシードを取る（タイトルのデモも同様）。
ページを3回開き直して開始し、3回とも異なる展開になることを実ブラウザで確認した。

8・9面の編隊ごとの配置パターン。種類・機数・出現間隔の骨格は `rounds.js` の固定データ。

広い盾の敵（ガード）は、5面（紹介）では常に編隊の先頭。8・9面は編隊ごとに乱数で2択：

- **後から来る護衛**：先頭2体（ガンナーとウィーバー）が盾なしで先行し、約2.5秒後にガードが来て、
  後ろから層を渡ってくるシフターを覆う。盾は本体の0.3手前まで届くため、先行する2体が盾の外に出るよう間隔を取った。

| 8面 後から来る護衛 | 100% | 54/60 | 12/12 |
| 9面 先頭に盾 | 3% | 52/60 | 12/12 |
| 9面 後から来る護衛 | 100% | 55/60 | 12/12 |
| 8面／9面 混在（実際の出現） | — | 58/60・53/60 | — |

「後から来る護衛」は倒す順番を実際に変える。3つ目の案（盾の陰のウィーバーが盾の外へ出る）は、

### 空の盤面では次の敵をすぐ出す（2026-09-29）

### 紹介動画（2026-09-29）

`media/twin-vector.mp4`（768×864、30fps、H.264＋AAC モノラル、20秒）と `screenshot.gif`（512×576、30fps、20秒）。
タイトル4秒（デモの操作役が戦っている場面）→ Spaceで開始 → ゲーム16秒（開始曲4秒＋1面12秒）。

制作中に音源の不具合を発見・修正した：音量の既定値1のまま音符を開始していたため、開始時刻が大きいと
丸めで1サンプルだけ最大音量のクリックが漏れていた（実プレイでも経過時間とともに起こり得た）。
音量の初期値を0にして解消。ブラウザ検査に「18秒台で開始した全音源が0.2を超えない」を追加し、
修正前の音源では失敗することを確認した（63項目）。

### 正式版としての配備（2026-09-29）

`docs/twin-vector/` に配備。開発時の記録 `evidence/`（画面写真・bot記録・旧版エンジン）は同梱せず、
開発用の `tmp/games/twin-vector/` にのみ残す。本文中の `evidence/...` への言及はその開発用コピーを指す。

- 画面写真や測定結果を書き出すテスト（`browser`、`feel`、`balance`、`boss-balance`、`view`）は、
  実行時に `evidence/` を作ってそこへ出力する。この出力はgit管理外（ルートの `.gitignore`）。
- 旧版エンジンと比べる履歴用のテスト `nine-stage-balance.cjs`、`calibrate-human.cjs`、`expansion-balance.cjs` は
  旧版エンジンが `evidence/` にあるため同梱しない（開発用コピーで実行できる）。
