# HEAD RUSH

セガ『ヘッドオン』（1979）の同心四角形レーンと逆走ライバルを、
『パックマン チャンピオンシップエディション』のようにテンポと爽快感を上げて組み直した、
ドットイート・レースゲーム。フラッグを取るたびに半分ずつコースの形が変わる、3分間のスコアアタック（CLASSICから始まる）。

## タグ

使用していない。ユーザーの指示（ヘッドオン型ドットイート × CE的スピード・爽快感）が十分具体的だったため、
AGENTS.md に従い `pick-tags.mjs` は実行していない。

## 想定する完成版と前提

深夜のサーキット、5本の周回レーンに撒かれたドットを、逆走してくる赤い車をかわしながら食べ尽くす。
完成版はCEと同じく「コース（レーンの形・ギャップの位置・駐車スポット）が異なる複数のステージ」×
「5分／10分のタイムアタック」×「ハイスコア」構成を想定。ステージごとにギャップの数や配置が変わり、
「最後にギャップを通るのはどちらか」の読みが変化する。

このスライスは3分のスコアアタック1モード・トップ5で構成（当初あった5分ツアーと開始コース選択は廃止。10分モードやステージ演出は未実装）。

## 操作

| 操作 | キー |
|---|---|
| 開始 | Space / Enter / Z / X |
| レーン変更（中心へ／外へ） | 矢印キー / WASD — 次に通るギャップで、画面上の向きどおりに曲がる（上辺なら↓が内側） |
| 加速（押している間） | Space / Shift / Z / X |
| 一時停止 | P（ウィンドウから離れても停止、任意のキーで復帰） |
| 消音 | M |
| ネーム入力 | 矢印で文字盤を移動、Space / Enter / Z / X で決定（DEL・ENDあり、20秒で自動確定） |
| ゲームパッド | 十字キー／左スティック＝矢印、A・B・R1＝加速（兼 開始・決定）、START＝開始／一時停止 |

- 方向キーは押した時点で **次のギャップまで予約**され、自車のウインカー（橙）が点滅する。
  そのギャップを通り過ぎると予約は消える。タップは何回押しても1レーン（重ねがけしない）。
- **押しっぱなしならギャップの中で続けて複数レーンを渡れる**（ヘッドオンと同じく、遅いほど多く渡れる）。
  通常速度では**最大2レーン**、**加速中は1レーン**（当初は低速で最大3レーンだったが、狙った所で止めやすくするため2に変更）。
- 2レーン目以降は、同じ方向を **0.2秒以上押し続けている** ときだけ渡る。普通の押し方ならギャップ直前でも必ず1レーン。
  複数レーン渡りたいときはギャップの手前から押し続ける。押し続けが十分になるとウインカーが2点になる。
- **進路の予測線**：ギャップの48px手前からギャップを抜けるまで、今の入力（予約・押し続け・加速）のままならどのレーンへ渡り、
  次のギャップまでどう走るかを、自車の前方に黄色の破線（進行方向へ流れる2×2の点）で示す。次のギャップの手前に太い横棒。自車の進路だけで、ライバルの動きは含まない。
  予測は本体と同じシミュレーションを他の車を除いて先回しして作るので、実際の結果と食い違わない（全パターン×入力×速度段階×開始レーンの150通りで一致を確認）。
- タッチ：自車のレーンより内側をタップで内へ、外側で外へ。2本目の指を置いている間は加速（Playwrightのタッチ模擬でのみ確認、実機未確認）。

## ルール

- 自車は反時計回り、ライバルは時計回り。車線変更はギャップでのみ。自車は上記のとおり1〜2レーン、ライバルは常に1レーン。
- ギャップの位置・つながるレーン・向きはコースごとに違う（下表）。一方通行のギャップは壁の切れ目に山形の印（内向き／外向き）があり、ライバルも同じ制限を受ける。
- ライバルは自車より遅く（速度段階0で自車の75%、段階10で95%）、ギャップの60px手前で矢印のウインカーを出し、その時点の自車レーンへ1レーン寄せる（確率は速度段階とともに30%→100%）。
  ギャップの手前では、ライバルがウインカーどおりに曲がって次のギャップまで走る進路が赤い破線で出る（その先の曲がりは予測しない）。
  出したウインカーは変わらない。**最後にギャップを通った側が、すれ違いのレーンを決める**。
- 同じレーンで正面衝突するとクラッシュ（1機失い、約2.2秒の損失、隊列は解散）。初期3機、3千点で1機、以後5千点ごとに1機（8千・1.3万・1.8万点…、最大6機）。
  **時間切れ（TIME UP）か、残機がなくなる（GAME OVER）と終了**。控えの車は画面下の左に表示。
- 画面左右の半分それぞれのドットを食べ切ると、反対側の半分のギャップにチェッカーフラッグが立つ。
  取ると食べ切った半分が復活し、**速度が1段階上がり**、駐車車が1台増える（最大8台）。
- 灰色の駐車車の上を通ると目を覚まし、ライバルの隊列の最後尾へ飛んで加わる。隊列はライバルの走った軌跡をそのままなぞる。
- 各半分に1つあるパワー（橙の四角）を取ると、隊列全体が青くなって逃げ始める（ギャップで自車から離れるレーンへ）。
  このあいだは **正面衝突が得点** になり、200→400→800…と倍々（上限12,800）。隊列を全部食べるとパワーは即終了し、追跡が再開する（トラックが残っている間は終了しない）。
  食べた直後の0.8秒は、パワーが切れても他の車に当たってもクラッシュしない（すり抜ける。自車が白く点滅）。
- 連鎖の途中でレーンを変えてから次の車を食べると、その1台は2倍（SWITCH）。ライバルの軌跡が曲がった所を追いかけて食べ続けるための報酬。
- 速度段階3から紫のトラック（クルーザー）が1台、段階6から2台走る（パワー中は他の車と同じく青くなり、紫のストライプと「+1」で区別できる）。時計回りで**レーンを一切変えない**。
  ぶつかればクラッシュ。パワー中なら食べられ、**点は入らないがベース倍率が×1→×2→×3…と上がる（ゲーム中ずっと、クラッシュで×1に戻る）**。
  赤い車の得点は「200点 × ベース倍率 × 連鎖倍率（そのパワーで食べた順に ×1, ×2, ×4, ×8 …）」で、**掛け合わせた合計は×64（1台12,800点）まで**。ベース倍率に上限はない。
  ベース×2なら赤い車は ×2, ×4, ×8 …、×3なら ×3, ×6, ×12 … で入る。（`TRUCK_MAX` でベースに上限を設けた場合、上限後のトラックは赤い車と同じように加点される）。
  画面には正確な倍率を出す：食べた車の点数の上に「×N」、トラックを食べると「BASE ×N」、中央の箱にはパワー中は次の赤い車の倍率、それ以外はベース倍率（紫）。
- **フラッグを取ると、ドットが復活する側の半分が別の形（ハーフパターン）に切り替わる**（CEの「フルーツで半面の迷路が変わる」に相当）。
  もう片方の半分はギャップも残りのドットもそのまま。レーンは共通なので車はそのまま走り続ける。変わった半分は壁とドットが黄色く明滅し、画面下にその半分のパターン名が3秒間出る（FEASTは続く間ずっと金色で表示）。
- ハーフパターンは5種（CLASSIC / TWIN GATES / UNDERTOW / LONG STRAIGHT / LADDER）＋ボーナスの FEAST。
  切り替わる順番は固定：開始コースの次から易しい順（CLASSIC → TWIN GATES → UNDERTOW → LONG STRAIGHT → LADDER → 先頭へ）。その半分と同じ形の番は飛ばす。左半分の定義を右半分では180°回転して使う。
  上辺中央のギャップは「自車（反時計回り）が左半分に入る入口」として左半分に属し、右半分では下辺中央になる。
- 3分間。CLASSICから始まり、フラッグごとに半分ずつ形が変わる。

## デザインと表現

詳細は [VISUAL_DESIGN.md](VISUAL_DESIGN.md)。要約：

- 1979〜81年ごろのアーケードを想定した固定画面（240×272を整数倍に拡大）。夜のサーキットを管制塔から見た構図。
  青い二重線のバリア、滑走路灯のような白いドット、ストライプとヘッドライト付きの太い車。
- 色はすべて役割に対応：黄＝自車、赤＝追ってくる車（濃い赤が隊列）、紫＝レーンを変えないトラック、青＝パワー中のライバル、
  白＝ドット、橙＝パワーとウインカー、明るい青の山形＝一方通行。
- 車は13×9、トラックは17×9（当たり判定は変えていない）。タイヤは走行に合わせて2コマで明滅。ドット3×3、パワー6px、フラッグ10×12。
- 文字は自作の5×7ビットマップ（6px送り）。時間は上部中央に2倍、ロゴは4倍に赤い影。外部素材・フォント・CDNなし。
- 演出の強さは出来事の重さに比例：ドット（短いクリック。途切れずに食べ続けると音階が上がる）< レーン変更（タイヤ痕、車体が新しいレーンへ傾く）<
  半面の食べ切り（壁が明滅、自車からフラッグへ光が走り、フラッグが降りてくる）<
  フラッグ（黄色の四角い波紋、半面のドットが明滅、外側から内側へレーンを光が走り、新しい速度ピップが点滅）<
  クラッシュ（一瞬止まってから両車が来た方向へ回転しながら弾かれ、衝突の向きに画面が揺れる）<
  連鎖（食べるたびにヒットストップが伸び、音程が上がり、波紋が大きくなる。食べた車は白くなって回転しながらコースの外へ撥ね飛ぶ。連鎖が長いほど速く飛ぶ。5連鎖以上は白い波紋と大きな得点表示）。
- パワーを取ると隊列が先頭から最後尾へ順に青くなる（隊列の長さ＝取れる連鎖が一目で分かる）。加速中は後ろに2本の排気が伸びる（速度段階とともに長く）。残り5秒は毎秒、時間が3倍の赤で出る。
- 音は**セガ System 1（1983）の音源部に相当**：SN76489A を2個（2MHzと4MHz、モノラル0.40：0.60）。BGMは2MHz側（メロディ・和音アルペジオ・ベース・ノイズのドラム）、
  効果音は4MHz側（効果音2音、3チャンネル目＋ノイズでエンジンのうなり）。音程は10ビットの分周値で決まる飛び飛びの値、音量は2dB刻み16段階、60Hzのドライバ。
  BGMはトランス・テクノ風の8小節ループ（Am F C G | Am F G E）。ベースのチャンネルで4つ打ちのキック（音程の急降下）と裏打ちベースを交互に鳴らし、
  16分のトランスゲート・アルペジオ（3-3-2のアクセント）、1小節2音の静かなパッド（明るいメロディはパワー中だけ）、7小節目のブレイクダウンと8小節目のスネアロール。
  速度段階とともにテンポが129→225BPMに上がり層が増える。パワー中はメロディが和音の構成音を駆け上がる8分のフレーズに替わる。詳細は [AUDIO.md](AUDIO.md)。
- 紫のトラックは車体とキャビンが分かれた長いシルエットで、赤い追跡車と形でも区別できる。
- 残り時間はレーン中央の箱に表示。速度段階は上部のピップ（黄→橙→赤）。

## 核となる相互作用と主な判断

一文の感覚：**最後のギャップで1レーンずらして赤い車を紙一重でかわし、パワーを取った瞬間には逆に自分からその車線へ飛び込み、隊列を一台ずつ撥ね飛ばしていく。**

- 判断の中心は「次のギャップで曲がるか、どちらへ、加速するか」。価値は、自車とライバルそれぞれの次のギャップまでの距離と
  合計接近速度で決まる。加速は出会う地点をずらして「最後に動く側」を入れ替える道具だが、加速中はギャップで1レーンしか逃げられない。
  減速していれば2レーン一気に逃げられる（ライバルは1レーンずつしか寄せられない）。
- パワー中は同じ読みで目的が反転する：すれ違いを避けるのではなく、同じレーンで出会うように最後に動く。
- 駐車車を起こすのは、隊列を長く（危険に）する代わりに、次のパワーで得られる連鎖を伸ばす投資。
  駐車車はドットのあるレーン上にいるので、いつ起こすかは避けにくい選択になる。
- 得点・進行の出来事：ドットを通過（10点）、フラッグ取得（速度段階＋1、500×(段階+1)点）、パワー中の正面衝突（連鎖得点）。
- 難度上昇：フラッグごとに両者の速度が15%ずつ上がり、ライバルが寄せてくる確率が上がり、駐車車が増える。
  速くなるほど1回のギャップで渡れるレーン数が3→2に減る。レーン・ギャップの配置とウインカーは変わらないので、判断の形は読めるまま速くなる。

## このスライスで確かめたいこと

1. ヘッドオンの「最後に動く側が勝つ」読みが、生存（避ける）と得点（パワー中に飛び込む）の両方の技能として働くか。
2. 自分で伸ばす隊列（駐車車を起こす）がリスクとして感じられ、パワーの連鎖で報われるか。
3. 「速いほど小回りが利かない（加速中は1レーン）」がCE的なスピード感を損なわず、加速押しっぱなしを退ける判断になっているか。

## 意図的に省いたもの

10分モード、ボーナスステージ、コース間の演出、アトラクトでのルール実演（アトラクトは人間制限botが実際に遊ぶデモと、トップ5表の交互表示のみ）、
CEの「爆弾（ゴーストを巣へ戻す）」相当の救済手段、ウインカーでだますライバル（中心の読みを壊すため不採用）、
残り時間が少ない時のギャップ強調表示（効果が薄いと判断し見送り）。

## 起動

`index.html` をブラウザで直接開く。ビルド不要。HTTPで配信する場合：

```sh
python3 -m http.server 5173 --directory docs/head-rush
```

## テスト

Playwright はリポジトリルートの `node_modules` を使用する。

```sh
cd docs/head-rush
node tests/rules.cjs         # コア規則（103項目：レーン変更、ライバル、隊列、パワー、コース／一方通行、クルーザー、SWITCH、半面の切り替え、ドット位置）
node tests/browser.cjs       # 実キー入力のフロー（49項目：アトラクトの循環、開始、操作、一時停止、連鎖、クラッシュ、残機切れ、ネーム入力→表→タイトル×2など）
node tests/feel.cjs          # 手応えの契約（27項目：パワー中のトラックの色、撥ね飛ばし、クラッシュの残骸、ウインカーの即時点灯、arm／加速の音、ドットの連続、パワーの色の波、半面の食べ切り、速度アップ、残り5秒）
node tests/audio.cjs         # 音の契約（39項目：音程・音量・ノイズの実機仕様、同時発音と取り合い、長さ、全イベントの割り当て、BGM、再現性、音割れ）
node tools/render-audio.cjs  # BGM（速度段階ごと・パワー中）と効果音一式、プレイ相当のミックスを evidence/audio/ にWAVで書き出す
node tools/record-video.cjs  # タイトル4秒＋プレイ16秒を media/head-rush.mp4（音あり）と screenshot.gif に書き出す（Playwright と ffmpeg が必要）
node tests/input-devices.cjs # ゲームパッド（差し替え）とタッチ（模擬）の10項目
node tests/balance.cjs 16 3  # 方策ラダー
node tests/shots.cjs         # オラクル操作の画面
node tests/courses-shot.cjs  # 全コースの画面
```

開発時の `evidence/`（画面写真・試聴用WAV・計測ログ）は `docs/` には置いていない（`tmp/games/head-rush/evidence/` に残してある）。
テストや上のツールを実行すると `evidence/` が作り直されるが、Git の管理対象外。

`HR_C='{"GAPW":12}' node tests/balance.cjs` のように環境変数でコア定数を上書きしてスイープできる（Nodeのみ）。

## 調整の記録

方策ラダー（`bots.js`）：
- オラクル：完全情報、2ギャップ先までの計画（1つ目は最大2レーン）×加速3方式、3.3秒先読み、0.1秒ごとに再計画。
- 人間制限：ライバルの車線変更を約0.27秒遅れて認識、位置の読み誤差、30%の確率で隊列の尾を見落とす、
  1ギャップ先の計画（2レーン移動はギャップ手前から押し続け、2レーン目の後にリズムで離す、±33msの誤差）・2.2秒先読み、タップの時間誤差（σ≈75ms）、加速の切り替え遅れと最短押下時間、判断は毎秒4〜5回。

主な構造変更（いずれも上記ラダーで確認）：

| 観察 | 変更 | 結果 |
|---|---|---|
| 加速押しっぱなしが人間制限でもオラクルでも最適（オラクル：常時74k vs 選択47k） | 加速中はギャップで曲がれない | 押しっぱなしは600点（idleと同じ）に。ただし人間制限のクラッシュの41%が「加速したまま曲がれなかった」 |
| ユーザー指摘：ヘッドオンは低速なら1ギャップで複数レーン渡れる | 押しっぱなしで複数レーン（通常3→高段階で2）、加速中は1レーン。タップは重ねがけしない | 下表。人間制限 28.5k→37.2k、オラクル（6シード平均）約80k→約112k。加速押しっぱなしは16k（オラクル選択の約1/7）で、支配的には戻らない |
| ユーザー実プレイ：低速で1レーンだけ動くのが難しい（普通の押下0.1秒で2レーン目に入っていた） | 2レーン目以降は0.2秒以上の押し続けが必要。十分に押すとウインカーが2点に | 普通の押下（ブラウザテストで110ms）は必ず1レーン。人間制限 33.5k/5.6回→35.3k/6.5回、オラクル 72k→95k（誤差の範囲）。botは押下時間の誤りを再現しないため、この判断はプレイ報告に基づく |
| クラッシュで速度段階が下がり、人間制限では段階が0付近に張り付く | クラッシュは時間と隊列だけを失う | 人間制限で終盤の段階が0.2→約4 |
| パワー4個＋長い逃走時間で、プレイ時間の31〜41%がライバル不在 | パワーは半面に1個、隊列を食べ切るとパワー即終了 | ライバル不在は3〜6%に。連鎖は計画して取るものに |
| ライバルがギャップ侵入時に判断するため、避けられない状況が多い | 手前40pxでウインカーを出して確定 | 「相手の確定後に動く」読みが可能に |

## 既知の未検証事項・制限

- ユーザーの実プレイ報告（1レーン移動が難しい）を受けて押し続け判定を入れたが、修正後の実プレイは未確認。
  （その後、渡れるレーンの上限を2にしたため、「ちょうど2レーンで止める」難しさは解消した。）
- 上級速度（段階7以上）での読みやすさは手で確かめる必要がある。
- 手応えの強化（「操作感の調整：手応えの強化」の項）は `tests/feel.cjs` で状態と音の割り当てを確認し、フレームを撮って目で確認した（`evidence/feel-*.png`）。ユーザーの実プレイで了承済み。
  パワーの色の波は「新しいパワーで開始時刻が記録され、パワー中に取り直しても始め直さない」ことだけを自動で確認し、隊列の何台目が何フレーム目に青くなるかは画面でのみ確認。
  車体の傾き（1px）とタイヤ痕は小さく、自動テストもない。arm の音は、ギャップから遠い所で押し続けても鳴る（2点目のウインカーの表示と同じ条件）。
- タッチ操作は模擬のみで実機未確認。ゲームパッドは `getGamepads` の差し替えでのみ確認し、実機未確認。
- 音はSN76489A×2のモデルで生成（AUDIO.md）。スピーカー／ヘッドホンでの試聴とBGMの出来は未確認。`tools/render-audio.cjs` のWAVで試聴できる。タブ切り替えでの停止・再開は擬似的な visibilitychange でのみ確認（ヘッドレスではタブが実際に隠れない）。
- SWITCH（レーン変更をはさんだ連鎖2倍）で、オラクルの得点が大きく伸びた（13.7万→24.2万）。人間制限botはほとんど取れない（ツアーで1.7回）。上級者向けの報酬として残しているが、実プレイで得点の偏りを確認したい。
- 人間制限botのクラッシュは3分で約6〜7回。半面の切り替え先は固定の順番（易しい順）、FEASTは固定スケジュール。
- 人間制限botは本作専用のモデルで、実プレイヤーに合わせた較正はしていない。
- 3分でフラッグは人間制限で約4本（速度1.6倍程度）、オラクルで約8本。CEほど速度が上がりきらない可能性がある。

### 2. モード

5分ツアーを追加（後に廃止。当初はフラッグ2本ごとにコース全体を切り替えていたが、下の「フラッグでの半面切り替え」に置き換えた）。

### 3. ライバルの種類

紫のトラック（クルーザー）のあり・なし（CLASSIC、人間制限24シード・オラクル3シード）：人間制限 39.7k→36.6k（クラッシュ7.0→7.5）、
オラクル 95k→137k（パワー中に食べて連鎖に使う）。段階3以降の人間制限botのクラッシュのうち約27%がトラックとの衝突。
上手いほど得をし、下手なほど危ない障害物になっている。

### 4. 連鎖の掘り下げ

SWITCH（連鎖中にレーンを変えてから食べると2倍）を追加。上の「既知の未検証事項」のとおり、上級者との差を大きく広げている。

### 5. アーケードの仕上げ（arcadifying-mini-games / building-era-authentic-game-audio を使用）

- TIME UP → （トップ5なら）ネーム入力 → トップ5表 → タイトル。表はモード別（スプリントはコース別）、既定の5件は読み出し時に合成し保存しない、同点は新しい記録を上位に。
- ネーム入力は文字盤方式（DEL・END付き）。入力直後の決定キーは20フレーム無視。
- タイトルのデモは毎回ランダムなコースで人間制限botが遊び、約15秒ごとにトップ5表を重ねる。デモは記録を書かない。
- BGMは上記の layered-adaptive 方式。操作軸は速度段階の1つだけ（＋パワーの切り替え）。一時停止・非表示では、エンジン音もBGMも止まる。

### 修正：ギャップにはみ出すドット

壁の切れ目はギャップ中心から±12px、ドットは±10pxまで置いていたため、切れ目の中にドットが見えていた。
ドットはギャップ中心から16px以上離す（`C.DOT_CLEAR`）ように全コース共通で修正し、規則テストで固定。ドット数は CLASSIC で188→172。
人間制限（16シード）34.8k／7.1回／フラッグ4.8 → 40.2k／7.7回／5.3で、大きな変化はない。

### 修正：フラッグでの半面切り替え（ユーザー指摘）

当初のツアーは「フラッグ2本ごとにコース全体を切り替え」だったが、CEと同じく「フラッグで復活する半分が別の形になる」方式に変更し、ツアーのコースクリアは廃止した。

- 既存4コースはすべて180°対称なので、左半分のパターン＋その回転としてそのまま分解できた。新パターン LADDER（側面に2つのギャップ）を追加。
- 半分同士が独立するよう、半分の境目（上下の中央）でドット列を必ず区切り、境目の余白もギャップの有無によらず一定にした。
  全125通りの組み合わせで「片方のパターンがもう片方のドットを動かさない」ことを規則テストで確認（最初の実装では境目の余白が相手側のギャップに依存していたのをこのテストで発見）。
- 切り替え時は、残りドット・駐車車の位置（最寄りの空きスポットへ）・各車のギャップ判定を引き継ぐ。
- 角にかかるギャップの修正：LADDER（±44→±30）と TWIN GATES（±40→±36）のギャップが内側のレーンで角をはみ出し、片側からしか使えない状態になっていた。
  修正前、人間制限botの LADDER 側のクラッシュは7.3回/分、修正後2.7回/分。「どのギャップも、つなぐ各レーンの辺に収まる」を規則テストで固定。
- 人間制限bot（SPRINT CLASSIC開始、24シード）：切り替えなし 41.5k／7.9回／フラッグ4.9 → あり 39.1k／9.2回／5.0。
  切り替え後に難しいパターンが出るぶんクラッシュが増える（半分ごとのクラッシュ率：CLASSIC 1.8、LADDER 2.7、UNDERTOW 4.9、LONG STRAIGHT 5.2、TWIN GATES 5.3 回/分）。
  切り替え直後2秒以内のクラッシュは全体の13%で、切り替えそのものによる事故は目立たない。オラクル 147k、TOUR 人間制限 93k／20回、idle 600、連打 6.7k。

### 追加：進路の予測線（ユーザー提案）

ギャップの手前とギャップ内で、今の入力を続けた場合の自車の進路を次のギャップまで点線で表示。
特に「押し続けで何レーン渡るか」（通常速度で最大2レーン）と「どこまでその車線に縛られるか」が、渡る前に見える。
ライバル側の予測は出さない（相手の動きはウインカーで読む、という核の読みを残すため）。
ブラウザでは実キー入力で予測レーン＝実際のレーン、ギャップから離れると非表示を確認。

### ビジュアルの拡張（ユーザー指摘：文字とキャラクタが小さく迫力に欠ける、予測線が薄い）

directing-game-visuals の手順で役割と色を固定したうえで、描画だけを変更（当たり判定・レーン・ゲームの数値は不変）。

### 調整：一方通行とLONG STRAIGHTの制約（ユーザー質問「一方通行は厳しすぎる？」）

各パターンを両半分に置き、半面切り替えなしで人間制限bot 10シードずつ測定（「避けられない」＝衝突1秒前にどの計画でも回避できなかった割合）。

| パターン | 点 | クラッシュ | 避けられない | フラッグ |

| CLASSIC | 40k | 8.3 | 6% | 5.2 |
| UNDERTOW（入口は内向きのみ・側面は外向きのみ）→ **側面を両方向に** | 22k → 38k | 7.8 → 10.4 | 21% → 8% | 3.8 → 5.7 |
| LONG STRAIGHT（側面の2か所のみ）→ **内側3レーン用の入口ギャップを追加** | 41k → 47k | 9.7 → 7.7 | 51% → 32% | 5.6 → 4.5 |

UNDERTOW は「潜るのは入口だけ」の性格を残しつつ、側面で必ず逃げられるようにした。外側レーンだけ一方通行にする案は効果がなかった（28%）。

### 調整：初見で避けられない問題（ユーザー実プレイ：3分で20回以上のミス）

人間制限botは約8回、誤差を最大まで入れても約14回で頭打ち。一方、何もしない＝17.6回、ライバルを無視してドットだけ追う＝21.9回で、
ユーザーの回数は「避けていない」水準だった。botを弱くするのではなく、危険を読めるようにし、序盤を易しくした。

- ライバルの速度を自車の100%→75%（速度段階ごとに+2%、最大95%）。
- 寄せてくる確率を段階0で55%→30%（段階ごとに+7%、段階10で100%）。ウインカーを40→60px手前に、2pxの点→矢印に。

### 修正：復活した敵が目の前に出る（ユーザー報告）

新しい先頭車は「駐車中の車のうち自車から一番遠いもの」だったため、連鎖の直後などで全員が近くにいると、20pxの距離で出現していた
（人間制限bot 12シードで、出現73回中9回が80px以内、そのうち7回は2秒以内にクラッシュ）。

- 車が現れてよい場所の規則：自車から110px以上、かつ自車と同じレーンの前方200px以内ではない（駐車に適用。先頭車の出現は後述の「後ろ側に出す」規則に変更）。
- 安全な駐車車がいなければ、一台がいったん遠くの安全な場所へ飛び、着いた所から先頭車になる（内側レーンを回り続けても先頭車が出ない、という抜け道を作らないため、着地時に再判定しない）。
- 新しい先頭車は0.75秒その場で白く点滅して待ち、その間は当たらない。
- 結果：出現の最短距離 20→114px、80px以内 9→0回、出現後2秒以内のクラッシュ 7→1回。

### 追加：ボーナス半面 FEAST（CEのパワーエサが大量に出る迷路に相当）

- 半面の切り替え先として、**3本目、7本目、11本目…（4本ごと）のフラッグで必ず現れる**（確率なし）。両半分同時・同じ半分で連続になる場合は次のフラッグへ繰り下げ（消えない）。開始コースにはならない。
- その半分はレーンの角すべて（10か所）にパワー、普通のドットは半分の密度。壁が金色になり、下のパターン名も金色。
- FEASTのパワーは通常の半分の長さで、取るたびに残り時間に加算（上限は通常の1個分）、連鎖は続く。隊列を食べ尽くせばパワーは終わるので、
  「エサ→車→エサ→車」とつなぐルート取りと、それまでに起こしておいた駐車車の数が得点を決める。
- 検証（SPRINT、CLASSIC開始）：FEASTなし→あり。人間制限 46k→59k（FEASTでの得点 23%）、オラクル 106k→182k（31%）、
  初心者モデル 35k→39k、ライバル無視 11k→17k、何もしない 600→600。技能の差は広がり、得点の3分の1程度に収まっている。

### 調整：後半のパワー時間（ユーザー指摘「後半のパワーアップ時間が短すぎないか」）

パワー時間は「5.2秒 − 0.28秒×速度段階（下限2.4秒）」で、段階10では2.4秒（FEASTでは1.2秒）だった。

|---|---|---|---|
| 5.2→2.4秒（旧） | 68% ／ 67% | 11% | 4〜6% |

採用後のSPRINT（CLASSIC開始）：人間制限 66k／6.0回、初心者モデル 29k／9.4回、ライバル無視 17.6k、オラクル 178k／0回。

### 調整：渡れるレーン数の上限（ユーザー提案「高速時は1レーン、低速時は最大2レーン」）

押し続けると低速で最大3レーン渡れたが、2レーン目と3レーン目の間が約0.1秒しかなく、ちょうど2レーンで止めるのが難しかった。

### 修正：赤い車がしばらく出ない（ユーザー指摘）

パワー中以外で赤い車がいない時間が最長9.9秒あった（人間制限bot、4コース×8シード）。原因は2つ。
赤い車がいない間に駐車車の上を通ると、その車が遠くの駐車スポットへ飛び、「飛んでいる車がいる間は新しい赤い車を出さない」条件で待ち時間がリセットされていた
（外側のレーンを走ると駐車車を次々に起こし、いつまでも出ない）。また、駐車車が1台もいない時は戻り待ち（最大2.5秒）が終わるまで出なかった。

- 赤い車がいない時に起こした駐車車は、遠くの安全な場所へ飛んでそのまま新しい赤い車になる。
- 待ち時間を止めるのは「赤い車になる予定の車が飛んでいる間」だけ。
- 駐車車がいなければ、戻り待ちの車を待たずに遠くの安全な場所へ出す（出現時の0.75秒の待機つき）。
- 結果：赤い車がいない時間は最長9.9秒→1.4秒（9割は1.3秒以内）。「パワー中以外は2.5秒以内に戻る」を規則テストで固定。

### 操作感の調整：手応えの強化（描画と音のみ）

ゲームの規則と数値は変えず、描画と効果音だけを変更した。優先度順：

1. **食べた車を撥ね飛ばす**：食べた車はヒットストップ中は衝突した位置に留まり、その後、自車の進行方向と外側へ回転しながら飛ぶ（連鎖が長いほど速く、回転も速い）。
   最初は青のままにしたが、画面で見ると生きている隊列と区別できなかったため、白い車体（ストライプは元の色）にした。
2. **ウインカーを押した瞬間に点灯**：点滅の位相を押すたびに始め直し、最初の8フレームは点灯したまま（以前は最大4フレーム消えたままのことがあった）。
   押し続けが足りて2点目が点いた瞬間に短い音（`arm`）。
3. **レーン変更**：横移動中は車の前半分を新しいレーン側へ1pxずらして「切り込む」形に。出た位置にタイヤ痕。1回のギャップで2レーン目を渡ると音程の上がる音を足す。
   横移動そのものの緩急（ease-out）も試したが、当たり判定が見た目の位置で行われるため、人間制限botの得点が 60.3k→45.5k、初心者モデルが 23.7k→12.7k（32シード）と大きく変わった。
   見た目のための変更でゲームの結果が変わるので取り消した（取り消し後はbotの結果がもとと完全に一致することを確認）。
4. **加速**：後ろに2本の排気（速度段階とともに長く）、押した瞬間に短いノイズ音（`boost`）。
5. **ドットの連続**：途切れずに食べ続けると1粒ごとに音階が1段上がり、6段の後は上の2音を交互に鳴らす。レーン変更か、ドットのない区間（ギャップの切れ目など）で最初に戻る。開始の音程は従来どおり速度段階で上がる。
6. **半面の食べ切り**：壁が明滅し、自車から新しいフラッグへ光の粒が走り、フラッグが上から降りてくる。最初は壁を白一色で光らせたが、フラッグより目立ったため薄い色の明滅に弱めた。
7. **速度アップ**：フラッグを取ると、外側のレーンから内側へ順に光が走り、新しい速度ピップが点滅する。
8. **クラッシュ**：4フレーム止まってから、自車とぶつかった相手が来た方向へ回転しながら弾かれる。画面は衝突の向きに沿って揺れる。
9. **パワー**：新しくパワーが始まると、隊列が先頭から1台3フレームずつ遅れて青くなる。
10. **残り5秒**：毎秒、時間が3倍の赤で出てから戻る（カウントダウンの音は以前からある）。

ニアミスの段階化は、ニアミスそのものを削除したため取りやめた。
パワー中のトラック（ユーザー指摘「紫の敵がパワー中に青くならない」）：紫と白の点滅をやめ、他の車と同じ青い車体に紫のストライプにした。食べられることは青で、ベース倍率を上げる特別な獲物であることはストライプと「+1」で伝える。
テスト追加時に見つけた不具合：ヒットストップの最後の1フレームで食べた車が動き出していた（コアはその1フレームを止めたまま stop を0にするため）。ヒットストップに入っていたフレームは止める判定に直した。
確認：規則101・音36・ブラウザ49・入力機器10項目が通過。ブラウザで各出来事の前後のフレームを撮って目で確認（エラーなし）。

### 6. 操作まわり

ゲームパッド（十字キー／左スティック／A・B・R1／START）を追加。タッチの判定を長方形レーンに対応させた。

### 修正と調整：パワーの終了条件、メロディ、初速、開始音、動画（ユーザー指摘・指示）

- **パワーの終了条件（ユーザー指摘）**：赤い車を食べ切ると、紫のトラックが残っていてもパワーが即終了していた。
