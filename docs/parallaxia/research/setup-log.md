## Phase 2 — Canvas の土台と計器

決めたこと（著者の指定が無かった部分）:

| 項目 | 選んだもの | 理由 |
| --- | --- | --- |
| 言語 | 素の JavaScript（ES モジュール） | ビルド工程が無く、`index.html` をそのまま配信できる。シムを Node からそのまま読める |
| ビルドツール | なし | 同上。変えるなら `docs/remake-decisions.md` の F1 |
| テスト | Node 標準のテストランナー | 追加の依存が無い |
| ブラウザの自動操作 | Playwright 1.63.0（Chromium） | 依頼書の想定どおり。スキル同梱のスクリプトが前提にしている |
| 乱数 | xorshift32 | 状態が整数 1 個で、状態ハッシュに含めやすい |
| Canvas の大きさ | 480×640（仮）。著者の決定（B1: 原作どおり）を受けて、2026-10-08 に 640×480（中央 320 px がフィールド）へ変えた | — |

スキル同梱のスクリプトは `tools/vendor/` に写して使った（スキルはリポジトリの外にあり、絶対パスで参照できないため）。

計器ごとの確認:

| 計器 | 通ること | 壊したフィクスチャで失敗すること |
| --- | --- | --- |
| 1. 決定的な実行 | 確認した（同じシードと入力で同じハッシュ。Node とブラウザでも一致） | 確認した（`Math.random` を使うシム、シードを無視するシム、入力を無視するシム、DOM と時計に触れるシム） |
| 2. スモークテスト | 確認した | 確認した（入力でクラッシュするページ。入力の段階のエラーとして検出されることまで見ている） |
| 3. 画面写真 | 確認した（指定フレームで止まる。同じ条件なら同じ画像、違うフレームなら違う画像） | 壊したフィクスチャは用意していない |
| 4. メカニクスの検査 | 確認した（デバッグ用ハンドルの契約を調べるプローブ 1 本） | 確認した（期待値が間違っているプローブ）。ロックオンのプローブは未実装のためスキップ |
| 5. 弾の軌跡のトレース形式 | 確認した（書き出しと検証） | 確認した（ヘッダなし、数値でない欄、フレームの逆行、同じ弾の重複） |
| 6. 方策の比較 | **ゲームに対しては未実施（スキップ）**。枠はおもちゃのシムで確認した | 確認した（押しっぱなしが最適なシムを失敗と判定する。単調な方策が 0 点のときは比を未定義とする） |
| 7. 絶対パスの検査 | 確認した | 確認した（POSIX のパス、Windows のパス、このマシンのホームディレクトリ） |

途中で見つけて直した問題:

- スモークテストの呼び出しが、配信サーバーを止めてしまう形になっていた（同期的に子プロセスを待っていた）。
  このとき自己検査は「ページが読み込めない」という別の理由で失敗し、**通ったように見えていた**。
  呼び出しを直し、自己検査は「入力の段階でエラーが出た」ことまで確かめるようにした
- 絶対パスの検査が、スクリプト冒頭の `#!` の行を検出していた。検査する範囲を、ホームや一時ディレクトリなど環境に依存するパスに絞った
- npm のキャッシュがサンドボックスで書けなかったので、一時ディレクトリをキャッシュに指定して入れた
