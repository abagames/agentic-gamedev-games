## 選ぶときに確かめること

どの候補も、次の点は **未確認** である（コードを読んでも動かしてもいない）。

1. **決定性**: `$rand` に外から乱数を渡せるか。内部で `Math.random` を使っていると、シード付きの再現ができない
2. **固定タイムステップ**: 1 フレームずつ進められるか（2.0 の説明には経過時間を渡す更新が出てくる）
3. **状態の直列化**: 実行中の弾幕の状態を、プレーンなデータとしてシムの状態に入れられるか。
   入れられないと、状態ハッシュとリプレイの検査（`npm run check`）の対象から弾幕が外れる
4. **原作の拡張への対応**: 原作は「弾が別の弾幕を実行する発射元になる」「左右反転」「速度ランクによる倍率」を
   BulletML の外側で実装している。ライブラリの上に載せられるか
5. **DOM への依存**: XML の解析に `DOMParser` を使っていると、Node 単体でシムを回せない
6. **速度の単位**: 原作は記述上の速度に 0.161 を掛けている。ライブラリ側の単位との対応

## 判断の目安

- 原作の XML をそのまま使うなら、互換性の検証が要る。最小の確認は、XML を 1 つ読み込み、
  弾の軌跡をトレース形式（`src/sim/trace.js`）で出して、シードを変えずに 2 回実行して一致するかを見ることである
- 弾幕を新しく書き直すなら、XML にこだわる理由は薄い。JavaScript のデータやジェネレータで書くほうが、
  状態のハッシュと相性がよい
- 上の 1・3・5 のどれかを満たせないライブラリは、このリポジトリの検査の前提と合わない
