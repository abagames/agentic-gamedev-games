# PARALLAXIA

PARALLAXIA は、PARSEC47（ABA Games、2003）の現代的リメイクである。ブラウザの素の Canvas（2D）で動く縦スクロールの弾幕シューティングで、ゲームエンジンやフレームワークは使っていない。作業担当は Claude Code。

置き場所は、リポジトリ agentic-gamedev-games の `docs/parallaxia/` である。下のパスとコマンドは、このディレクトリを基準にしている。

**完成したビルドである**（2026-10-12、著者の判断。プレイ感覚、見た目、音は、著者が遊んで Ok とした）。経緯は `REVISION_HISTORY.md` にある。

入っているもの: 無限に続く SECTOR（10 で一巡、5 と 10 がボス）、3 つのモード（CHAIN、CLOSE、GRAZE）、到達した 10 ごとの SECTOR からの開始、
小型の編隊と 21 種の飛行パターン、中型 8 種・大型 7 種の飛び方、SECTOR ごとに決まった敵と弾幕（生成したものを固定している）、一巡ごとに上がるランク、
周回ごとに解禁される内容と性格のある区間、下を流れる地形と地上物、ロックオンレーザー、体当たり、ミスと残機、モード別の得点倍率（x1〜x16）とエクステンド、
命中や撃破の演出、効果音とジングル、ファミコンの 5 チャンネルの枠で作った BGM 5 曲（`docs/audio.md`）、タイトル画面、モードと開始 SECTOR ごとのハイスコア。

操作:

- タイトル: 左右でモード（CHAIN、CLOSE、GRAZE の順。初めて開いたときは CHAIN）、上下で開始 SECTOR（選べる向きの矢印が、行の上と下に出る。タッチは行の上半分・下半分）（到達した 1、11、21…。どのモードで到達しても、全モードで開く）を選び、ショットで始める。モードは敵弾の速さと密度、自機の速さが違う
- キーボード: 矢印キーか WASD で移動。ショットは Z、X、J、K、スペース、Enter のどれでもよい（下の「Z」は、このどれでも同じ）。タイトルでは Z で始める。ゲームオーバーのあとは、Z でタイトルに戻る。M で音（効果音と BGM）を消す・戻す。P でポーズ
- ゲームパッド: 左スティックか十字キーで移動。ショットは、右側の 4 つのボタン、左右の肩のボタン、左右のトリガーのどれでもよい（実機では未確認）
- タッチまたはマウス: ドラッグで移動し、触れている間はショットが出る
- ショットは、自機の幅いっぱいのツインショットが真上に出る（扱いは幅のある 1 発）。画面上に同時 4 発までなので、敵に近いほど速く撃てる。倒した点数には x1〜x16 の倍率が掛かる（画面上端の RATE）。倍率の稼ぎ方はモードで違う: CLOSE は相手に近いほど高く、CHAIN は編隊を逃がさず全滅させるたびに上がり、GRAZE は敵弾にかするたびに上がって時間で下がる。敵の本体に触れるとミスになる
- 下を、いろいろな並べ方の地上が流れる。地上物は攻撃せず、ぶつかることもないが、ショットはそこで止まる。壊せば点数が入るだけで、逃がしても何も失わない。ふつうのパネルのほかに、金色のボーナスの的（組をすべて壊すとボーナス）、ショットを止める壁（4 発で壊れる）、撃つまで見えない隠れた的、壊すとまわりも壊れるコア（ロックオンできる）がある。どこに何があるかは SECTOR ごとに決まっている
- SECTOR 5 と 10（以後も 5 つごと）はボスである。本体と翼を別々に壊せて、翼を壊すとしばらく撃たなくなる。翼をすべて壊してから本体を倒すと、連鎖に入る。中ボスは 15 秒、大ボスは 24 秒たつと上へ去り、その 3 秒前に予告が出る
- ロックオン: ショットを押し続ける（触れ続ける）と、前方の大きい敵、ボスの各部、地上のコアにロックがたまる（最大 4）。離すとレーザーが出る。まとめて放つほど 1 本が強い

画面は縦長で、見た目は 1980 年代のラスター方式の業務用基板風である。フィールドは画面より少し広く、自機の左右の移動に合わせて画面が左右にスクロールする。画面の外にいる敵は弾を撃たない。見た目は、最初に 4 案（線画、1980 年代ラスター、ベクタースキャン、フラット）を作って比べ、著者が選んだ。

## 始め方

```sh
npm install                       # Playwright を入れる
npx playwright install chromium   # 初回だけ
npm run check                     # 全検査
npm run serve                     # http://127.0.0.1:8047/ で開く
```

Node 22 以上が要る。ES モジュールを使っているので、`index.html` はファイルを直接開くのではなく、`npm run serve` で配信して開く。

飛行パターンを 1 つだけ見るには `http://127.0.0.1:8047/?drill=hook` のように開く。`[` と `]` で前後に切り替え、数字キー 1〜9 でも選べる。選べるのは次の 22 種である（`stairs` は練習モードだけ）:
`column`、`diagonal`、`hook`、`hover`、`dive`、`hairpin`、`sweep`、`stairs`、`wave`、`zigzag`、`cross`、`loop`、`pincer`、`duck`、`split`、`orbit`、`ladder`、`lace`、`swoop`、`bounce`、`stagger`、`curl`。
`&middle=1` で中型を足し、`&mflight=stalk` のようにすると中型の飛び方を 1 つに固定する（`sink`、`post`、`stalk`、`drift`、`sway`、`guard`、`slant`、`drop`）。
`&large=1` と `&lflight=patrol` は大型で同じことをする（`descend`、`patrol`、`shift`、`retreat`、`circuit`、`lunge`、`strafe`）。

手を入れるときは、Claude Code を起動して指示する。指示書は `AGENTS.md` である。

## 分かっている制限

- 登場中のボス（SECTOR 5 と 10 の開始から約 1.5 秒）は撃てないが、触れるとミスになる。画面の上のほうにいると、降りてくるボスに当たる（開始から 40 フレーム後に当たることを確かめた）。直していない
- 得点の表示は 9 桁である。10 億点以上は欄からはみ出す
- ハイスコアは、ゲームオーバーになったときに保存される。途中でページを閉じたプレイは残らない
- ゲームパッドだけで始めると、キーかタッチに一度触れるまで音が出ない（ブラウザが、音を出す許可をゲームパッドの操作では与えないため）
- 写し（`snapshots/`）は公開していない。手元で 2026-10-12 より前の写しを本編と同じサーバーから開いて遊ぶと、そのハイスコアと開始 SECTOR の開放が本編の記録に混ざる（`complete` 以降の写しは記録を残さない）
- 確かめていないもの: 実機のスマートフォンでの操作と発音、ゲームパッドの実機、Chromium 以外のブラウザ、古い端末での処理速度。全体は `REVISION_HISTORY.md`（英語）の「Never measured, never checked」
- `docs/spec-draft.md` の SECTOR ごとの点検の表と、方策 `keeper` の連鎖・得点の表は、2026-10-12 の変更（敵弾の当たり判定、分裂の距離、WIDE と FAST、撃つ区間、急降下）より前の規則で測った値である。著者のリプレイ 3 本と、それに合わせた方策 `author` も同じ

## 検査

`npm run check` が全部を実行し、最後に一覧を出す。ログは `artifacts/check-log.txt` に残る。

| 計器 | コマンド | 中身 |
| --- | --- | --- |
| キーとポインタ | `node tools/check-browser.mjs` | 各操作に割り当てたキーがすべて、同じ入力ビットとしてシムに届く。ドラッグで自機が自分の速度で追従し、触れている間ショットが出る |
| 決定的な実行 | `npm test` | 同じシードと入力から同じ状態ハッシュが得られる。リプレイの記録と再生 |
| スモークテスト | `npm run smoke` | ヘッドレスの Chromium で起動・放置・入力を行い、コンソールエラーとクラッシュを検出する |
| 画面写真 | `npm run screenshot -- --frame 120 --seed 1 [--input 16] [--replay file.json] [--out file.png]` | 指定したフレームの画面を保存する |
| メカニクスの検査 | `npm run probe` | `probes/*.probe.mjs`。ブラウザで状態を注入し、具体的な値を確かめる |
| 弾幕の検査台 | `npm run trace -- --loop 2 --type 7 [--out file.jsonl]` | 生成された敵の型を 1 つだけ動かし、基本の形・ランク・分かれ方と 1 秒あたりの弾数を表示する。`--out` で弾の軌跡を書き出す（形式は `src/sim/trace.js`） |
| 方策の比較 | `npm run balance` | 単調な方策と探索的な方策のスコア比（exploratory_ratio）を出す |
| ページまわり | `node tools/check-shell.mjs` | タイトルから始まること、キーを押すまで音が出ないこと、消音、ゲームパッドの入力、ハイスコアの保存、ハンドルから読んだリプレイでの再現、`?rec=1` でのリプレイの保存 |
| 音 | `node tools/audio.mjs` | 音のキットの検証と、全部の音を実際に合成して測った音量（無音でない、振り切れない） |
| 飛行パターンの比較 | `node tools/flight.mjs --seeds design` | パターンごとの軌道の数値と、視界に制限のあるボットでの全滅率・ミス。`npm run check` には入っていない（判定の道具で、合否の検査ではない） |
| 絶対パスの検査 | `npm run check:paths` | このディレクトリ内のファイルに絶対パスが書かれていないこと |

### 検査の読み方

- **PASS** は、その検査が実際に何かを調べて通ったことを表す
- **SKIP** は、調べる対象がまだ無いことを表す。通ったという意味ではない。
  いまはスキップになる検査は無い
- 「self-test」と付いた項目は、計器をわざと壊したフィクスチャに向けて、**失敗することを**確かめている。
  たとえば、入力でクラッシュするページをスモークテストが検出できるか、である。
  単体テストの中にも同じ趣旨のものがある（`Math.random` を使うシムを決定性の検査が検出できるか、など）

### 方策の比較について

`npm run balance` は、放置・押しっぱなし・連打といった単調な方策の最高得点と、探索的な方策の最高得点を比べる。
比が 1.0 以下なら、単調な入力が最適ということなので失敗とする。

**これは退化を検出するためのもので、面白さを判定するものではない。** 比が高くても、遊んで面白いかどうかは分からない。
面白さは、人間が実際に触って判断する。

連鎖と得点の出方を見るときは `node tools/chain.mjs` を使う。連鎖を守るように動く方策 `keeper`（`tools/policies/keeper.mjs`）と `seeker` を比べる。

弾幕が逃げ場を残しているかは `node tools/dodge.mjs [--modes normal,rapid,dense] [--starts 31,61,91] [--policy keeper|author] [--room 2] [--save 6]` で見る。方策がミスした場面を 0.5・1・2・3 秒巻き戻し、自機の動かし方をすべて試して、ミスの瞬間とその 1 秒後まで生き残る道があったかを調べる（`tools/lib/dodge.mjs`）。
この道具は、弾を通り抜ける道を数えない。ゲームの当たり判定は、2026-10-12 まで、弾に向かって動く自機が弾をまたいで通り抜けるのを許していた（この道具の自己検査で見つかり、直した）。いまは、ゲームの判定だけで調べても（`--game-hits`）同じ結果になる。`--room 2` は、どの弾からも当たる距離の 2 倍を保つ道だけを数える。

人のプレイを数値で見るときは、`?rec=1` を付けて遊び、保存されたリプレイを `node tools/replay-stats.mjs <ファイルかディレクトリ>... [--policies author,keeper,seeker,keeper+human,seeker+human]` に渡す（下の「人のプレイの記録」）。

人間並みの方策は `author`（`tools/policies/author.mjs`）である。著者のリプレイ（`replays/`）に合わせて作ってあり、どこまで合っているかは `docs/human-bot.md` にある。比べ直しと数値の探索は `node tools/human-fit.mjs`。
以前の `humanLimited`（強い方策の入力を遅らせるだけのもの）は、著者より 3〜7 倍ミスが多く、難易度の話には使わない。方策比較の報告（`npm run balance`）の形式のために残してある。

探索的な方策は 2 つある。状態を見ない乱択と、画面を見て動く `seeker`（敵の正面に入り、弾と敵の本体を避ける）である。
`seeker` は 1 秒に約 10 回入力を変えるので、人間より正確である。難易度の判断には、人間並みに制限した方策の結果を見る。
報告の形式は evaluating-gameplay-balance スキルのログ形式に合わせてある。人間並みに制限した方策の結果は `profile_results` に分けて出る。

## デバッグ用ハンドル `window.__game`

ブラウザ側の検査は、すべてこのハンドルを通す。契約として維持する（項目を変えたらここも直す）。

| 項目 | 内容 |
| --- | --- |
| `contractVersion` | 契約の版。いまは 2（`mode`、`audio`、`replay()` を足した） |
| `mode` | `"title"` か `"play"`。下の `reset`、`step`、`runReplay` を呼ぶと `"play"` になる |
| `audio` | `{ log, muted, unlocked, music, held }`。`music` は鳴っている曲、`held` は P キーのポーズ中か。`log` は音のバスが下した判断の記録（`played`、`dropped`、`muted`、`hidden`、`repeat`） |
| `replay()` | 最後の `reset`（またはタイトルからの開始）以降の入力を、リプレイとして返す |
| `replayFile()` | `?rec=1` が保存するファイルの中身を、いまの時点のものとして返す（リプレイに `build`、`via`、`end` を足したもの） |
| `capabilities` | シムが実装しているもの（`scoring`, `gameOver`, `bullets`, `mechanics`）。検査はこれを見てスキップを決める |
| `state` | シムの状態そのもの。読み書きできる（状態の注入に使う） |
| `frame` | 現在のフレーム番号 |
| `paused`, `pause()`, `resume()` | 実時間のループを止める・再開する |
| `reset({ seed, mode, startSector, course })` | 指定したシードで最初からやり直す。`mode` は `normal`（既定）、`rapid`、`dense`。`startSector` は 1（既定）、11、21… |
| `title` | タイトルで選ばれているモードと開始 SECTOR、そのモードで開いている最後の開始 SECTOR |
| `step(n, input)` | ちょうど n フレーム進めて、実時間のループを止める。`input` を渡すとその間だけ入力を上書きする |
| `setInput(bits)` | キーボードの代わりにこの入力を押し続ける。`null` で解除 |
| `runReplay(replay, { maxFrames })` | リプレイを最初から再生し、状態ハッシュを返す |
| `hash()` | 現在の状態ハッシュ（16 進 8 桁） |
| `render()` | いまの状態を描画する |

URL の指定は次のとおりである。どれも検査と確認のためのもので、遊ぶのには要らない。

| 指定 | 内容 |
| --- | --- |
| `?seed=123` | シードを固定し、タイトルを飛ばして始める。付けなければタイトルから始まり、シードは始めるたびに変わる。**このプレイは記録に残らない**（ハイスコアも、開始 SECTOR の開放も保存しない） |
| `?mode=rapid` | モード（`normal`、`rapid`、`dense`）。タイトルは飛ばさない |
| `?start=11` | 開始 SECTOR。**`?seed=` と一緒のときだけ効く**（単独では無視する。到達していない SECTOR が開いてしまうため） |
| `?paused=1` | 止まった状態で、タイトルを飛ばして開く（道具がコマ送りするためのもの） |
| `?rec=1` | 終わったプレイをリプレイのファイルとして保存する（下の「人のプレイの記録」） |

写し（`snapshots/<ラベル>/`）から開いたプレイも、記録に残らない（規則の違うビルドの得点が、本編の記録に混ざらないように。2026-10-12 より前に取った写しは、この扱いになっておらず、本編と同じ保存先に書く）。写しは公開していないので、これは手元で開いたときの話である。
`?drill=<パターン>` は、飛行パターンを 1 つだけ流す練習モードである（`createSim({ seed, drill })`）。

入力は 5 ビットの整数である（`src/sim/input.js`）: 上 1、下 2、左 4、右 8、ショット 16。
キーボードは、矢印キーと WASD（移動）、Z・X・J・K・スペース・Enter（ショット）である。タッチとマウスのドラッグ、ゲームパッドも、同じ 5 ビットに変換される。

リプレイの形式は `{ "version": 1, "seed": 123, "frames": [[入力, フレーム数], ...] }` である（`src/sim/replay.js`）。

### 人のプレイの記録

URL に `?rec=1` を付けると、プレイが終わる（ゲームオーバーになる）たびに、そのプレイのリプレイがファイルとしてダウンロードされる。キーの操作は無い。付けなければ何も保存されない。
写しで遊ぶときは `snapshots/<ラベル>/index.html?rec=1` を開く。練習モード（`?drill=`）では保存されない。

ファイル名は `parallaxia-<ビルド>-<モード>-<開始 SECTOR>-<得点>-<日時>.json` で、中身はリプレイに次の項目を足したものである。

| 項目 | 内容 |
| --- | --- |
| `build` | 遊んだビルド。`snapshots/<ラベル>/` から開いたときはそのラベル、それ以外は `dev` |
| `via` | 自機を動かした入力の種類（`keyboard`、`pointer`、`gamepad`） |
| `end` | 終わった時点の `{ frames, score, sector, hash }`。`hash` は状態ハッシュ |

`node tools/replay-stats.mjs` は、このファイルを `build` の規則（`snapshots/<build>/src/sim/`。`dev` と、写しが無いときは作業中の `src/sim/`）で再生し、`end.hash` と同じ状態で終わることを確かめてから数値を出す。
合わないファイルは、遊んだときの規則と違うので、測らずにそう表示する。`dev` で保存したリプレイは、規則を変えると再生できなくなるので、あとで使うつもりなら写しで遊ぶ。

出る数値は、入力を変える頻度、同じ向きを押し続ける長さ、ショットを離す頻度、自機の位置、いちばん近い敵弾までの距離、ミスと連鎖切れの原因などである（`tools/lib/playstats.mjs`）。
`--policies` を付けると、同じシード・モード・開始 SECTOR を方策に同じ長さだけ遊ばせ、同じ数値を横に並べる（方策は 4 回の平均）。
著者のリプレイは `replays/` に置く（各モード 1 本）。このディレクトリは git に入れていないので、手元に無ければ `human-fit.mjs` は比べるものが無い。
見ているものと、危険が現れてから入力が変わるまでの遅れは、測っていない。

## 構造の約束

- シミュレーション（`src/sim/`）は DOM・時計・`Math.random` に触れない。三角関数は `src/sim/math.js` を使う（実行環境で結果が変わるため）。`npm test` が静的に調べている
- 状態はプレーンなデータ 1 個で、`stepSim(sim, input)` だけが進める
- 描画は状態を読むだけである。描画や音だけの変更で、状態ハッシュが変わってはならない
- 演出（粒、輪、段階のある爆発、機体の破片、点滅、画面の揺れ）は `src/render/fx.js` にあり、シミュレーションがそのフレームに出した出来事（`sim.events`）を見て動く。シミュレーションは演出を読まない
- ゲームループは 60 フレーム毎秒の固定タイムステップである
