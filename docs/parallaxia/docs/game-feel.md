# 手応えの演出（1 回目）

著者が最も良くしたい点（敵への打ち込み感と破壊）についての記録である。maximizing-game-feel の手順に沿っている。

## 方針

- 調子: 1980 年代ラスターの見た目に合わせ、**ピクセルの粒と輪、白い点滅、短い画面の揺れ**だけで作る。ぼかし、半透明、滑らかな変形は使わない
- 強さの配分: いちばん強い反応は、いちばん大きな出来事（大物の撃破、ミス）に取っておく。毎フレーム起きる命中は小さくする
- 演出はすべて描画側（`src/render/fx.js`）にあり、シミュレーションが出す出来事の一覧（`sim.events`）だけを見て動く。
  シミュレーションは演出を読まないので、演出を変えても遊びとリプレイは変わらない

## 見た目と当たり判定の関係

- 敵弾の図案を 7 ピクセルから 9 ピクセルに広げた。当たる範囲（半径 0.45 単位＝直径 9 ピクセル）より小さく描くと、見た目では当たっていないのにミスになるためである
- 当たらない間の弾（出てから 24 フレーム）は、暗い色の 3 ピクセルの「種」で描く
- 中型が押し戻されるのは描画だけで、当たり判定の位置は動かしていない
- 画面の揺れは最大 3 ピクセルで、必ず 0 に戻る。得点などの表示は揺らさない

## 確かめたこと・確かめていないこと

- 確かめた: 演出を入れても、同じリプレイの状態ハッシュが Node とブラウザで一致する。同じシードとフレームの画面写真が毎回同じになる
- 著者が遊んで「良い」と述べた（2026-10-08）。揺れの強さや粒の数の細かい調整は、まだしていない
- 確かめていない: 弾が多い場面で、粒や輪が弾の読みやすさを邪魔しないか。処理速度
- 効果音とジングルを入れた（2026-10-10、`docs/audio.md`）。人の耳での確認はまだである
- 編隊全滅・連鎖切れ・体当たりの反応（2026-10-10 追加）は、画面写真で出ることを確かめただけで、強さの調整はしていない。maximizing-game-feel の手順は通していない

画像は公開していない（レーザーで中型を倒した 4 フレーム後の画面写真が、手元の `docs/looks/arcade-explosion.png` にある）

## 段階のある爆発、時間差の誘爆、機体の破片（2026-10-11、試作）

著者の指示で、セイブ開発の作品（雷電II、バイパーフェイズ1）の破壊の作りを、この見た目に合わせて試している。
調べたのは文章の資料だけで、映像は見ていない。写したのは絵ではなく構造（段階、時間差、破片）である。
写しは `snapshots/2026-10-11-staged-blast/`。**まだ遊ばれていない。**

参考にした記述: 駒澤敏亘氏（初代『雷電』の爆発の作者）の「割れる → 白い光 → 赤い光 → 光が縮む → 煙が残る → 消える」「最初の 3 コマのあとに一瞬止める」「爆発を 3 コマ減らし、煙を 20 コマ増やす」（https://shmuplations.com/seibukaihatsu/ ）。
敵を壊すと破片が飛ぶこと（https://www.hardcoregaming101.net/raiden-ii/ 、https://www.hardcoregaming101.net/viper-phase-1/ ）。

| 出来事 | 反応 | 強さ |
| --- | --- | --- |
| 爆発 1 つ（`blast`） | 白い円が 1〜3 フレームで広がり（縁は黄）、大きいものは 2 フレーム止まる。続いて炎（赤の外側、黄の内側、白い芯）が縮み、最後に灰色の網点の煙が残って、星と同じ向きに流れながら薄くなる。円はすべて塗りつぶしと網点で、半透明は使わない | 大きさで変わる |
| 小型を倒す | 半径 5 ピクセルの爆発（煙は 8 フレーム）。粒 9 個と輪は以前のまま | 小 |
| 中型を倒す | 中央に半径 11 の爆発。5・10 フレーム後に左右で半径 7 の誘爆。機体が 3 片に割れて飛ぶ。得点・揺れ・背景の明滅は以前どおり、倒した瞬間 | 大 |
| 大型を倒す | 中央に半径 13 の爆発。5〜25 フレーム後に、両端、内側、中央の順で 5 回の誘爆（そのたびに小さく揺れる）。機体が 5 片に割れて飛ぶ | 大（中型より一段上） |
| ボスの翼を壊す | 大型と同じ爆発の連なり。破片は無い | 大 |
| ボスを倒す | 中央から外へ 6 フレームずつ遅れて 7 か所、続けて胴体のあちこちで 6 回、46 フレーム後に半径 24 の最後の爆発（揺れ 24 フレーム、背景の明滅）。得点の表示は倒した瞬間。破片は無い | 最大 |
| 機体の破片 | 機体の絵を縦に切った一片。3 フレーム白く、そのあとは暗い一色（中型は暗い橙、大型は暗い赤）で、灯りも陰影も無い。倒された敵の速度を引き継ぎ、外側の片ほど強く外へ飛ぶ。28〜60 フレームで点滅して、半径 5 の爆発になって消える | 小（当たり判定は無い） |

描く順は、破片と煙が敵の下、光と炎が敵の上で敵弾の下である。敵弾は、どの段階の爆発にも隠れない。

### 決めたこと（Assumptions）

- 撃破を伝えるもの（得点の表示、最初の揺れ、背景の明滅、音）は、倒した瞬間のまま動かしていない。遅らせたのは誘爆だけである
- 誘爆には音を付けていない。撃破の音（中型 0.38 秒、大型 0.58 秒、ボス 0.6 秒）が鳴っている間に収まるためである。ボスの最後の爆発（46 フレーム後）だけは、音が終わったあとに来る
- 倒された敵の形と速度は、描画側が毎フレーム覚えておいた位置から求めている（`fx.tracks`）。`destroy` の出来事には手を入れていないので、`src/sim/` は変わっていない
- 煙の色（`smoke`、`smokeThin`）を足した。色味の無い灰色で、弾（マゼンタ）とも報酬（黄）とも違う
- 自機のミスと地上物の破壊は、以前のままである

### 入れなかったもの

| 候補 | 理由 |
| --- | --- |
| 残骸が落ちて、地面でもう一度爆発する（雷電II） | 舞台が宇宙で、地面は島が流れてくる間しか無い。残骸が残ると、体当たりでミスになる本体と見分けにくい |
| 影、波紋 | 同上 |
| ボスの本体と翼の破片 | ボスは板を組んで描いていて、切り分ける絵が無い。爆発の連なりだけにした |
| 小型の破片 | 1 秒に何機も倒すので、弾の間に破片が増えすぎる |
| 破片の回転 | ピクセルの絵を回すと形が崩れる。平行移動だけにした |

### 確かめたこと・確かめていないこと

- 確かめた: `npm run check` がすべて通る（リプレイの状態ハッシュの一致、同じシードとフレームの画面写真の一致を含む）。`src/sim/` に差分が無い。
  中型・大型・ボスの撃破を数フレームおきに撮り、段階・誘爆・破片が出ること、敵弾が上に描かれることを見た（`artifacts/screenshots/blast-*.png`。ボスは耐久を書き換えて倒した）
- 確かめていない: 動いているところ（静止画しか見ていない）。弾が濃い場面で、大型の赤い粒や破片が弾の読みやすさを邪魔しないか。
  小型を続けて倒したときに煙がうるさくないか。処理速度（爆発は同時に 48 個、破片の組は 8 個まで）。セイブの作品の実際の見え方との近さ
