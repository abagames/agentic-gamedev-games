# 著者のプレイに合わせた方策 `author`

2026-10-12。著者のリプレイ 3 本（CLOSE・CHAIN・GRAZE を 1 本ずつ、いずれも得点を取りにいったプレイ）に合わせて、人間並みの方策を作り直した記録である。
難易度の調整はまだしていない。この方策は、その調整に使うためのものである。

- 方策: `tools/policies/author.mjs`
- リプレイ: `replays/`（ビルドは `snapshots/2026-10-11-rec/`）。git には入れていない（著者の決定）。手元にだけある
- 比較と探索: `node tools/human-fit.mjs`、表だけなら `node tools/replay-stats.mjs replays --policies author`

## 以前の人間並みの方策がなぜ外れていたか

以前の `humanLimited`（`tools/policies/index.mjs`）は、強い方策の入力の変化を、毎回 250 ms 遅らせて出すものだった。同じシードを同じ時間だけ遊ばせると、次のようになる（リプレイ 3 本、方策は 4 回の平均）。

| | 著者 | keeper+human | seeker+human |
| --- | --- | --- | --- |
| 生存（CLOSE / CHAIN / GRAZE） | 255 / 484 / 267 秒 | 28 / 36 / 34 秒 | 55 / 99 / 51 秒 |
| ミス／分 | 0.94 / 0.74 / 0.90 | 6.8 / 5.2 / 6.5 | 3.4 / 2.0 / 4.5 |
| 入力の変化／秒 | 6.3 / 7.3 / 5.3 | 4.3 / 4.5 / 4.1 | 4.1 / 4.1 / 3.9 |

外れていた点は二つある。

1. **入力は遅くも少なくもない。** 著者は 1 秒に 5〜7 回入力を変え、同じ向きを押す長さの中央値は 6〜8 フレームである。以前の方策は、これより少なく、長く押していた
2. **著者は「反応」で避けていない。** 著者のミス 14 回のうち、弾によるものは 13 回で、発射から 15 フレーム（1/4 秒）以内の弾に当たったものは 1 回も無い。いちばん早いもので 17 フレームである。
   弾は発射の 24 フレーム前から「種」として見えているので、著者はいつ・どこへ撃たれるかを先に知って動いている。入力を遅らせるだけの方策は、これができず、近くで撃たれるたびに当たる

## 方策の中身

計画の立て方は `keeper` と同じである（期限のある仕事を選び、モードの倍率に合わせて動く）。人であることを表すのは次の部分で、数値は著者のリプレイに合わせて探した。

| 性質 | 値 | 何に合わせたか |
| --- | --- | --- |
| 遅れて見る（`latency`） | 18 フレーム | 見ているのは 18 フレーム前の画面で、当時の動きのまま進めたもの。それより後に現れた弾や、向きを変えた敵は知らない。全体のミスの頻度に合わせた値で、反応時間を直接測ったものではない |
| 種の拍を知っている（`foresee`、`focus`） | 自機から 12 以内の種 | 種が出てから撃たれるまでの長さを知っていて、「撃たれる瞬間の自機の位置へ飛ぶ弾」として先に避ける。発射 15 フレーム以内のミスが無いことに合わせた。遠い種は数えないので、遠くからの弾には遅れて気づく（著者の弾によるミス 13 回のうち 7 回は、発射から 17〜34 フレームの弾） |
| 弾が多いと見失う（`free`、`lapse`、`wake`） | 6 発まで全部追う。12 発で半分を見失う。見失った弾は 2 まで近づくと気づく | 著者の弾によるミス 13 回のうち 6 回は、発射から 37 フレーム以上たった弾で、弾の多い場面（GRAZE、ボス、大型）に偏る |
| 位置の読みの誤差（`noise`） | 自機からの距離の 2% | 探索で残った値。効きは小さい |
| 決める間隔（`think`、`thinkJitter`） | 6〜11 フレームごと | 入力の変化の頻度 |
| レーザーを放つ数（`volley`、`stall`） | ロック 3 つ、または 12 フレーム増えなければ | 1 回に放つ数の平均（著者 2.8〜3.4） |
| モードごとの位置取り（`restY`、`below`、`ceilY`、`floorY`、`berth`） | CLOSE は編隊の 5 下・画面の中ほど、CHAIN と GRAZE は下寄り | 自機の y の分布、いちばん近い弾までの距離 |

`foresee` を 0 にすると（反応だけにすると）、発射直後の弾でのミスが主になる。これは単体テスト（`test/author.test.mjs`）で確かめている。

## 合っていないところ

- **CLOSE では、方策は著者より稼げず、早く終わる。** 得点／分が約 25% 低く（倍率 6.7 対 7.9、撃破 111 対 126）、ゲームオーバーまでの中央値は約 190 秒である（著者は 255 秒。32 回中 27 回が著者より早く終わった）。著者は、方策より近くで、方策と同じくらいのミスで倒している
- **一巡目のミスが著者より多く、二巡目以降が少ない。** 著者は一巡目の 5.9 分でミス 1 回、二巡目以降の 10.9 分で 13 回である。方策は、周回による差が著者ほど大きくない。難易度を周回ごとに決めるときは、この偏りを差し引いて読む
- 方策は著者ほど動き続けない（止まっている割合が CLOSE・CHAIN で 2 倍）。ショットを離す回数も少ない。GRAZE では逆に、著者のほうが止まっている
- CLOSE と CHAIN では、方策は著者より弾の近くにいる。GRAZE では撃破が著者より多い（129 対 101）

## この結果の確かさ

- **リプレイは各モード 1 本で、ミスは全部で 14 回である。** ミスの頻度の 95% 区間は、1 本あたり、おおよそ著者の値の 0.3 倍から 2.5 倍まである。方策のミスの頻度は、どのモードでもこの区間に入っているが、それ以上の細かさでは合っているとも外れているとも言えない
- 数値は 3 本に合わせて探したもので、ほかの人のプレイや、著者の別の日のプレイに当てはまるかは確かめていない
- 著者が何を見ているか、危険に気づいてから入力が変わるまでの時間は、測っていない。`latency` の 18 フレームは、ミスの頻度から逆に決めた値である
- 方策の計画は `keeper` のもので、著者の判断を写したものではない。合わせたのは、結果として現れる数値である

## 試して採用しなかったもの

- 見失う弾の割合を、弾の数によらず一定にする: 全体のミスの頻度は合うが、一巡目のミスが著者よりずっと多くなった（CLOSE で 1.12 回／分）
- 弾の数だけで見失う（遠い種も全部先読みする）: 弾の少ない CHAIN のミスが 0.1〜0.2 回／分まで下がり、著者の 0.74 に届かなかった
- 種が撃たれるときに近くにいないようにする（距離を保つ項）: ミスの頻度も内訳も変わらなかった
- 種を先読みしない（遅れだけ）: 発射直後の弾でのミスが CLOSE で毎分 0.5〜0.9 回出て、著者の 0 回と合わなかった

## モードごとの長さ（2026-10-12）

著者の方針で、1 プレイの長さを著者の水準で 5 分ほどに揃えることにした（`docs/remake-decisions.md`）。著者のリプレイは CLOSE 4 分 15 秒、GRAZE 4 分 27 秒、CHAIN 8 分 4 秒で、CHAIN だけが長い。
CHAIN は、エクステンドを無くしても、著者のリプレイで 6 分半（3 回目のミスが 390 秒）続いていたので、エクステンドの間隔（700,000 → 1,000,000）と敵弾の速さ（1.35 → 1.45 倍）の両方を変えた。CLOSE と GRAZE は変えていない。

`author` に、ゲームの残機のまま、ゲームオーバーまで遊ばせた結果（各 48 回、同じシード。25% ／ 中央値 ／ 75%）:

| CHAIN の設定 | 終了時刻 | 到達 SECTOR（中央値） | エクステンド（中央値） |
| --- | --- | --- | --- |
| 弾速 1.35、700,000（変更前） | 350 / 512 / 664 秒 | 46 | 3 |
| 弾速 1.35、1,000,000 | 289 / 434 / 534 秒 | 39 | 2 |
| **弾速 1.45、1,000,000（いま）** | **244 / 365 / 465 秒** | 33 | 1 |
| 弾速 1.5、1,000,000 | 209 / 298 / 401 秒 | 27 | 1 |
| 弾速 1.55、1,000,000 | 232 / 265 / 320 秒 | 24 | 1 |
| 弾速 1.6、1,000,000 | 181 / 232 / 301 秒 | 21 | 1 |

同じ測り方で、CLOSE は 111 / 172 / 276 秒、GRAZE は 184 / 218 / 337 秒である（どちらも変更なし）。

- 変更前の CHAIN で、`author` の中央値は 512 秒、著者は 484 秒だった。この比で読むと、いまの設定は著者で 5 分 45 秒ほどになる（CLOSE・GRAZE の約 1.3 倍）
- 弾速 1.45 を選ぶ前に出した見積もり（314 秒）は、残機を補充しながら遊ばせた記録から計算したもので、ここでの実測（365 秒）より 50 秒短かった。上の表のほうが直接の測り方である。5 分に合わせるなら 1.5 になる
- `author` は CLOSE で著者より早く終わる（172 秒対 255 秒）。CLOSE の数字は、著者の長さの見積もりには使えない
- 一巡目のミスは、弾速を上げてもほとんど増えない（毎分 0.15 → 0.21 回、残機を補充しながらの計測）。CHAIN の序盤が易しいことは変わっていない

## 当たり判定を直したあと（2026-10-12）

敵弾の当たり判定のすり抜けを直し、分裂を一定の距離にした（`docs/spec-draft.md`）。**この文書の「どこまで合ったか」は、直す前の規則（`snapshots/2026-10-11-rec/`）での比較である。** 著者のリプレイは直す前の規則のもので、新しい規則では再生できない。
直す前、著者はミス 14 回に対して 15 回、弾を通り抜けていた。直したあとの規則で著者がどのくらいミスするかは、遊んでもらうまで分からない。

`author` に、ゲームの残機のままゲームオーバーまで遊ばせた結果（各 48 回、同じシード。25% ／ 中央値 ／ 75%）:

| | 直す前（`snapshots/2026-10-12-chain-speed/`） | 直したあと |
| --- | --- | --- |
| CLOSE | 111 / 172 / 276 秒 | 73 / 118 / 170 秒 |
| CHAIN | 244 / 365 / 465 秒 | 195 / 247 / 301 秒 |
| GRAZE | 184 / 218 / 337 秒 | 124 / 174 / 207 秒 |

どのモードも 2〜3 割短くなった。`author` の数値は直す前の規則に合わせたままなので、新しい規則での著者との合い具合は確かめていない（`author` は通り抜けを当てにして動いてはいないが、直す前は結果としてそれに助けられていた）。
著者のリプレイが新しい規則で取れたら、合わせ直す。エクステンドと CHAIN の弾速も、そのあとで見直す。

## 作り直すとき

リプレイが増えたら `replays/` に置き、次で比べ直す。

```
node tools/human-fit.mjs                         # いまの数値での比較
node tools/human-fit.mjs --tune 2 --only common  # 全モード共通の数値を探す
node tools/human-fit.mjs replays/<CLOSE のファイル> --tune 2 --only close
node tools/human-fit.mjs --first 100 --variants 16   # 合わせるのに使っていない系列で確かめる
node tools/human-fit.mjs --free 16                   # ゲームオーバーまで
```

探索は、数値を 1 つずつ上下に動かして近づくものを残すだけの単純なものである。仕組みが合っていないと、数値を動かしても近づかない（上の「採用しなかったもの」は、そうして分かった）。
